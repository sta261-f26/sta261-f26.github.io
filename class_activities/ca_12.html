Consider the following data frame:

df = pd.DataFrame({
  "id" : [1, 2, 3],
  "bp_1" : [100, 120, 125],
  "bp_2" : [120, 115, 130],

  "hr_2" : [77, 81, 93]

In the lecture, we used wide_to_long to reshape this data:

pd.wide_to_long(df, stubnames = ['bp', 'hr'],

But now suppose the names of our columns are slightly different:

df = pd.DataFrame({
  "id" : [1, 2, 3],
  "bp_a" : [100, 120, 125],
  "bp_b" : [120, 115, 130],
  "hr_a" : [60, 75, 80],
  "hr_b" : [77, 81, 93]
})
TipQuestion

What happens if you try to use wide_to_long in the same way, to reshape this data frame?

pd.wide_to_long(df, stubnames = ['bp', 'hr'],
                i = 'id', j = 'stage', sep = "_")

The issue is that wide_to_long expects the suffix (everything after the underscore) to be a number – when it sees a letter instead (a or b), it gets confused.

The solution is to tell the function what type of suffix to expect! To do this, we can use a regular expression (we will see more of this later in the course):

pd.wide_to_long(df, stubnames = ['bp', 'hr'],
                i = 'id', j = 'stage', sep = "_",
                suffix = '.+')
bp hr
id stage
1 a 100 60
2 a 120 75
3 a 125 80
1 b 120 77
2 b 115 81
3 b 130 93

Avoiding listing columns

In the previous problem, you likely had to list many column stub names! This is tedious and error-prone. How can we avoid it?

One way is to extract the information we care about from the column names, with a regular expression. Here is one way we could do this (there are many different options, and it is ok if you don’t understand this code right now!):

measurement_types = set([s[0] for s in cleaned_data.columns.str.split('_') 
if len(s) > 1])

More wrangling

You work in the Office of Institutional Research at a large university, and your boss asks you to investigate the relationship between student evaluations and scores on the final exam in introductory statistics courses.

We have two CSV files to investigate this question. The exam_grades.csv file contains last semester’s final exam scores for 800 students taking introductory statistics across 30 different sections. The columns include:

  • student_id: a unique 4-digit identifier for each student
  • classid: which of the 30 sections the student was enrolled in
  • professor_name: the name of the professor which whom the student took the class. Each professor teaches several sections
  • exam_score: the student’s score on the final exam. All introductory students take the same final exam, regardless of course section

Your boss also provides you with information on each professor’s course evaluations. The professor_evals.csv file contains evaluations for each of the 10 professors teaching introductory statistics. The classid_1, classid_2, and classid_3 columns identify the 3 sections taught by each professor, while the three evalscore columns contain the professor’s corresponding course evaluation scores (out of 5) for each class.

You can import the data with

professor_evals = pd.read_csv("https://sta261-f26.github.io/class_activities/professor_evals.csv")
exam_grades = pd.read_csv("https://sta261-f26.github.io/class_activities/exam_grades.csv")
